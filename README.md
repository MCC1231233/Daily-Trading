# Daily Trading

코스피·코스닥 종목을 **정해진 정량 규칙**으로 매일 스크리닝해서, 일중 매매
(09:00 시가 매수 → 15:00 종가 매도) 관점의 후보 10종목을 뽑고 그 근거를
공개하는 도구입니다.

> **이것은 투자 추천이 아닙니다.**
> 공개 데이터에 `config.yaml`에 적힌 규칙을 기계적으로 적용한 **스크리닝 결과**이며,
> 특정 종목의 매수·매도를 권유하지 않습니다. 모든 지표는 과거 데이터 기반이라
> 미래 수익을 보장하지 않고, 표시되는 수익률에는 수수료·세금·슬리피지가
> 반영되어 있지 않습니다. 투자 판단과 그 결과는 전적으로 이용자 본인의 책임입니다.

## 보는 곳

**https://mcc1231233.github.io/Daily-Trading/**

매일 08:20 KST(장 시작 40분 전)에 자동 실행되어 갱신됩니다. 왼쪽 사이드바에
날짜가 쌓이므로 과거 리포트를 그대로 넘겨볼 수 있고, 채점이 끝난 날짜에는
그날 후보들의 실현 수익률이 함께 표시됩니다.

> Pages는 저장소가 공개일 때(또는 GitHub Pro 이상) 동작합니다. 비공개로 두는
> 경우 Actions 실행 결과의 `daily-trading-html` 아티팩트를 받아 여시면 됩니다.
> 데이터가 전부 인라인된 단일 파일이라 그대로 열립니다.

## 어떻게 뽑는가

### 1단계 — 유니버스 필터 (하드 게이트)

점수를 계산하기 전에 거르는 조건입니다. 하나라도 걸리면 탈락합니다.

| 조건 | 이유 |
|---|---|
| 관리종목·투자경고 제외 | 거래 제약과 변동성 구조가 다름 |
| 우선주·스팩·리츠·ETF 제외 | 일중 유동성과 공시 구조가 보통주와 다름 |
| 주가 2,000원 이상 | 호가 단위 대비 스프레드 부담 |
| 시총 3,000억 이상 | 수급 한 방에 휘둘리는 구간 배제 |
| 거래대금 100억 이상 | 진입·청산 슬리피지 방어선 |
| 전일 등락률 ±15% 이내 | 급등·급락 직후의 비대칭 갭 리스크 회피 |
| ATR 안전 상하한 1~25% | 국면과 무관하게 적용되는 안전 레일 |
| ATR 풀 내 10~85분위 | **상대 기준** — 아래 설명 참조 |
| RSI 78 이하 | 과매수 구간 신규 진입 배제 |

변동성 필터를 절대값이 아니라 **그날 후보 풀 안에서의 백분위**로 거는 것이
의도적인 선택입니다. 시장 전체 변동성은 국면에 따라 몇 배씩 달라지기 때문에,
고정 구간(예: 1.2~9%)을 쓰면 조용한 장에서는 아무것도 안 걸리고 험한 장에서는
거의 전부 탈락합니다. 실제로 이 저장소를 만든 날의 시장은 종목 ATR 중앙값이
11.3%였고, 고정 구간이었다면 후보의 3분의 2가 사라졌을 것입니다.

### 2단계 — 5개 블록 스코어링

각 팩터를 z-score로 표준화(±3σ 클리핑)한 뒤 블록별로 합산합니다.

| 블록 | 담는 것 |
|---|---|
| **수급** | 외국인·기관 5일 순매수(평균거래량 대비 %), 매수 우위 일수, 외국인 보유비율 변화, 동반 순매수 보너스 |
| **모멘텀** | 5일·20일 수익률, 지수 대비 상대강도, 20일선 이격도 |
| **일중 성향** | 과거 20일 시가→종가 평균·승률·샤프, 갭 상승일의 추세 유지 여부 |
| **기술적** | RSI·볼린저 %B의 중심값 이탈 정도(감점 방식), MACD 히스토그램, 거래량 급증비 |
| **펀더멘털** | 컨센서스 목표주가 괴리, 투자의견, PBR·추정PER |

**일중 성향 블록이 이 전략의 핵심입니다.** 보유 기간이 하루 6시간이므로
"20일 동안 얼마나 올랐나"보다 "이 종목이 원래 시가 대비 종가가 오르는
성향인가"가 전략에 직접 대응하는 질문입니다.

기술적 블록은 "RSI가 높을수록 좋다"가 아니라 **중심값(57)에서 멀수록 감점**
방식입니다. 단순 단조 증가로 두면 과매수 종목만 상위에 몰립니다.

### 3단계 — 국면별 가중치

코스피·코스닥의 20일선 위치로 국면을 나누고 블록 가중치를 바꿉니다.

| 국면 | 수급 | 모멘텀 | 일중 | 기술적 | 펀더멘털 |
|---|---|---|---|---|---|
| 위험선호 (둘 다 20일선 위) | 28% | 26% | 22% | 14% | 10% |
| 중립 (엇갈림) | 30% | 20% | 24% | 14% | 12% |
| 위험회피 (둘 다 아래) | 32% | 10% | 24% | 14% | 20% |

위험회피 국면에서 모멘텀 비중을 26%→10%로 줄이는 이유는, 지수가 20일선
아래일 때 추세 추종 신호의 이후 하루 수익률 분포가 나빠지기 때문입니다.

### 4단계 — 업종 분산

점수 순으로 뽑되 한 업종에 최대 4종목까지만 배정합니다. 같은 업종 10종목은
사실상 한 종목에 10배 베팅한 것과 같습니다.

## 성과 채점

매일 실행할 때 **직전 리포트의 후보들이 실제로 어떻게 됐는지 자동으로
채점**합니다. 각 종목의 그날 시가와 종가를 받아 `(종가/시가 - 1)`을 실현
수익률로 기록하고, 누적 통계를 사이드바와 성과 카드에 반영합니다.

사후에 규칙을 바꿔도 과거 채점 결과는 그대로 남으므로, 규칙 변경이 실제로
개선인지 확인할 수 있습니다. 휴장 등으로 시세가 없는 매매일은 `skipped`로
표시되어 통계에서 제외됩니다.

## 데이터 출처

KRX 정보데이터시스템 API는 2026년부터 로그인이 필요해져 사용하지 않습니다.

- **FinanceDataReader** — 전 종목 스냅샷(종가·거래대금·시총), 해외 지수·환율·VIX
- **네이버 금융 모바일 API** — 일별 시세, 투자자별 수급, 밸류에이션, 애널리스트 컨센서스
- **holidayskr** — 한국 법정공휴일(음력 명절·대체공휴일 포함) 판정

수집이 실패한 팩터는 중립값(z-score 0)으로 처리되고, 실패 건수는 리포트
상단에 표시됩니다. 한 종목의 수급 데이터가 빠졌다고 전체가 멈추지 않습니다.

## 구조

```
config.yaml                 규칙 파라미터 — 코드 수정 없이 여기만 바꾸면 됨
scripts/datasource.py       데이터 수집 (재시도·병렬·실패 격리)
scripts/factors.py          지표 계산 (RSI/MACD/ATR/일중 성향/수급)
scripts/screen.py           오케스트레이션 + 채점 + JSON 출력
scripts/build_standalone.py 데이터를 인라인한 단일 HTML 빌드 (Pages 대안)
docs/index.html             대시보드 (정적, data/*.json을 fetch)
docs/data/index.json        날짜 목록 + 누적 성과 (사이드바가 읽음)
docs/data/YYYY-MM-DD.json   그날의 리포트 전문
.github/workflows/daily.yml 08:20 KST 자동 실행 → 커밋 → Pages 배포
```

## 직접 돌려보기

```bash
pip install -r requirements.txt
python scripts/screen.py
```

`docs/index.html`은 `fetch`로 데이터를 읽으므로 파일을 직접 열면 동작하지
않습니다. 로컬에서 볼 때는 서버로 띄우세요.

```bash
python -m http.server 8000 --directory docs
```

## 규칙 바꾸기

`config.yaml`만 수정하면 다음 실행부터 반영됩니다. 필터 임계값, 블록 가중치,
국면별 배분, 업종당 상한이 모두 거기 있습니다. 바꾼 뒤에는 Actions 탭에서
`Daily Screening`을 수동 실행(`workflow_dispatch`)해 결과를 바로 확인할 수
있습니다.

## 한계

- 스크리닝은 **전일 종가까지의 정보만** 사용합니다. 당일 갭, 장중 뉴스,
  실적 발표, 공시는 반영되지 않습니다.
- 실현 수익률은 시가 체결·종가 체결을 가정한 이론값입니다. 실제로는
  슬리피지와 호가 공백이 발생합니다.
- 팩터 가중치는 과거 데이터로 최적화한 값이 아니라 **사전에 정한 값**입니다.
  과최적화는 피했지만, 그만큼 이 가중치가 최선이라는 근거도 없습니다.
- 임시공휴일·특별 휴장은 `holidayskr` 갱신에 의존합니다.
