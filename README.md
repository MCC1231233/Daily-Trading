# Daily Trading

**낙폭이 과다한 저평가 우량주를 09:00 시가에 매수해 15:00 종가에 매도**하는
전략을 정량 규칙으로 코드화해, 매일 후보 10종목과 그 근거를 공개하는 도구입니다.

추세 추종이 아니라 **역추세(평균회귀)** 전략입니다. 많이 오른 종목이 아니라
많이 빠진 종목이 상위에 오도록 팩터 부호가 설계되어 있습니다.

> **이것은 투자 추천이 아닙니다.**
> 공개 데이터에 `config.yaml`에 적힌 규칙을 기계적으로 적용한 **스크리닝 결과**이며,
> 특정 종목의 매수·매도를 권유하지 않습니다. 모든 지표는 과거 데이터 기반이라
> 미래 수익을 보장하지 않고, 표시되는 수익률에는 수수료·세금·슬리피지가
> 반영되어 있지 않습니다. 투자 판단과 그 결과는 전적으로 이용자 본인의 책임입니다.

## 보는 곳

**https://mcc1231233.github.io/Daily-Trading/**

매일 07:40 KST(장 시작 80분 전)에 자동 실행되어 갱신됩니다. 왼쪽 사이드바에
날짜가 쌓이므로 과거 리포트를 그대로 넘겨볼 수 있고, 채점이 끝난 날짜에는
그날 후보들의 실현 수익률이 함께 표시됩니다.

> **Pages 최초 설정**: Settings → Pages → Source를 `GitHub Actions`로 한 번
> 지정해야 합니다. 워크플로에서 자동화할 수 없습니다 — Pages 생성 API가
> `administration:write`를 요구하는데 `GITHUB_TOKEN`은 그 스코프를 가질 수
> 없어서 `Resource not accessible by integration`으로 실패합니다.
>
> Pages를 쓰지 않는 경우(비공개 저장소 등)에는 Actions 실행 결과의
> `daily-trading-html` 아티팩트를 받아 여시면 됩니다. 데이터가 전부 인라인된
> 단일 파일이라 그대로 열립니다.

## 어떻게 뽑는가

### 1단계 — 대상 조건 (낙폭 과다인가)

| 조건 | 이유 |
|---|---|
| 관리종목·투자경고 제외 | 거래 제약과 변동성 구조가 다름 |
| 우선주·스팩·리츠·ETF 제외 | 일중 유동성과 공시 구조가 보통주와 다름 |
| 주가 2,000원 이상 / 시총 3,000억 이상 | 호가 스프레드, 수급 취약성 |
| 거래대금 50억 이상 | 진입·청산 슬리피지 방어선 |
| **52주 고점 대비 -20% 이상 하락** | 낙폭 과다의 직접적 정의 |
| **20일 수익률 -45% ~ +3%** | 상단은 "안 빠진 종목" 배제, 하단은 구조적 붕괴 배제 |
| **RSI 15~58** | 과매도 구간. 15 미만은 되돌림이 아니라 추세적 붕괴인 경우가 많음 |
| 전일 등락률 -12% ~ +8% | 급락 직후는 갭 리스크가 비대칭이라 하루 쉬어감 |
| ATR 안전 상하한 1~25% | 국면과 무관한 안전 레일 |
| ATR 풀 내 10~85분위 | 상대 기준. 단, 통과 종목이 40개 미만이면 미적용 |

### 2단계 — 우량성 게이트 (falling knife 방어)

**이 전략의 최대 위험은 하락에 실제 이유가 있는 경우입니다.** "좋은 종목"이라는
조건이 그 방어선이며, 하나라도 어기면 탈락합니다.

| 게이트 | 이유 |
|---|---|
| EPS > 0 (흑자) | 적자 기업의 낙폭은 반등 근거가 약함 |
| 애널리스트 목표주가 존재 | 기관이 들여다보는 종목 = 정보 공백 리스크가 낮음 |
| ROE 2% 이상 | 자기자본 대비 최소 수익성 |
| PBR 5배 이하 | '저평가' 전략에 고PBR을 담을 이유가 없음 |
| 목표주가 상승여력 5% 이상 | 컨센서스 기준 저평가 확인 |
| **하락 다음날 일중수익률 ≥ 0%** | 아래 설명 |

마지막 게이트가 이 전략의 핵심 검증 장치입니다. **전일 하락한 다음 날의
시가→종가 수익률**은 이 전략의 매매 조건과 정확히 같은 상황에서의 과거
성적입니다. 가중 합산에만 넣어두면 다른 블록 점수에 묻히는데, 실제로 게이트
없이 돌렸을 때 상위 10종목 중 5종목이 이 값이 음수였습니다. 낙폭도 크고 싸고
수급도 좋지만, 정작 하락 다음 날 반등하지 않고 더 빠져온 종목들이었습니다.
표본이 10일 미만인 종목은 판단 불가로 보고 통과시킵니다.

### 3단계 — 5개 블록 스코어링

각 팩터를 z-score로 표준화(±3σ 클리핑)한 뒤 블록별로 합산합니다.

| 블록 | 담는 것 |
|---|---|
| **낙폭** | 52주 고점 대비 낙폭, RSI, 볼린저 %B, 20일선 이격도 |
| **반등** | 하락 다음날 일중수익률·승률, 전일 저가 회복률, 항복 거래량, 일중 평균 |
| **수급** | 외국인·기관 5일 순매수, 매수 우위 일수, 외국인 보유비율 변화, 동반 매수 보너스 |
| **저평가** | 목표주가 괴리, PBR, 추정PER, 배당수익률 |
| **우량성** | ROE, 투자의견, 일중 움직임의 일관성(샤프) |

낙폭 블록은 "많이 빠질수록 좋다"가 아니라 **-25% 부근에서 멀수록 감점**
방식입니다. -70% 같은 극단 낙폭은 되돌림이 아니라 훼손일 확률이 높습니다.
RSI(32), 볼린저 %B(0.15)도 같은 sweet spot 방식입니다.

수급 블록은 이 전략에서 단순 선호가 아니라 **검증 장치**입니다. 빠지는 종목을
외국인·기관이 사고 있다면 시장이 저점 매집으로 보고 있다는 뜻입니다.

### 4단계 — 국면별 가중치

| 국면 | 낙폭 | 반등 | 수급 | 저평가 | 우량성 |
|---|---|---|---|---|---|
| 위험선호 (둘 다 20일선 위) | 30% | 24% | 20% | 16% | 10% |
| 중립 (엇갈림) | 24% | 24% | 22% | 18% | 12% |
| 위험회피 (둘 다 아래) | 14% | 22% | 28% | 16% | 20% |

**국면 판단의 방향이 추세 전략과 반대라는 점에 주의하세요.** 지수가 20일선
아래인 위험회피 국면에서는 과매도가 더 과매도로 가기 쉬워 평균회귀가 잘
듣지 않습니다. 그래서 낙폭 비중을 30%→14%로 줄이고 수급·우량성으로 방어합니다.

### 5단계 — 업종 분산

점수 순으로 뽑되 한 업종에 최대 3종목까지만 배정합니다. 낙폭은 업종 단위로
동시에 발생하는 경우가 많아 추세 전략보다 쏠림이 심합니다.

### 후보 부족 경고

이 전략은 모든 게이트를 통과하는 종목이 시장 국면에 따라 크게 줄어듭니다.
후보가 12개인 날의 "상위 10종목"과 120개인 날의 "상위 10종목"은 의미가 전혀
다른데 화면에는 똑같이 10개가 보입니다. 그래서 리포트 상단에 **통과 종목 수
대비 선정 비율**을 표시하고, 2.5:1 미만이면 경고를 띄웁니다.

## 성과 채점

매일 실행할 때 **직전 리포트의 후보들이 실제로 어떻게 됐는지 자동으로
채점**합니다. 각 종목의 그날 시가와 종가를 받아 `(종가/시가 - 1)`을 실현
수익률로 기록하고, 누적 통계를 사이드바와 성과 카드에 반영합니다.

사후에 규칙을 바꿔도 과거 채점 결과는 그대로 남으므로, 규칙 변경이 실제로
개선인지 확인할 수 있습니다. 휴장 등으로 시세가 없는 매매일은 `skipped`로
표시되어 통계에서 제외됩니다.

## 데이터 출처

KRX 정보데이터시스템 API는 2026년부터 로그인이 필요해져 사용하지 않습니다.

- **FinanceDataReader** — 전 종목 스냅샷(종가·거래대금·시총), 해외 지수·환율·VIX
- **네이버 금융 모바일 API** — 일별 시세, 투자자별 수급, 밸류에이션, 애널리스트 컨센서스
- **holidayskr** — 한국 법정공휴일(음력 명절·대체공휴일 포함) 판정

수집이 실패한 팩터는 중립값(z-score 0)으로 처리되고, 실패 건수는 리포트
상단에 표시됩니다. 한 종목의 수급 데이터가 빠졌다고 전체가 멈추지 않습니다.

## 구조

```
config.yaml                 규칙 파라미터 — 코드 수정 없이 여기만 바꾸면 됨
scripts/datasource.py       데이터 수집 (재시도·병렬·실패 격리)
scripts/factors.py          지표 계산 (RSI/MACD/ATR/일중 성향/수급)
scripts/screen.py           오케스트레이션 + 채점 + JSON 출력
scripts/build_standalone.py 데이터를 인라인한 단일 HTML 빌드 (Pages 대안)
docs/index.html             대시보드 (정적, data/*.json을 fetch)
docs/data/index.json        날짜 목록 + 누적 성과 (사이드바가 읽음)
docs/data/YYYY-MM-DD.json   그날의 리포트 전문
.github/workflows/daily.yml 07:40 KST 자동 실행 → 커밋 → Pages 배포
```

## 직접 돌려보기

```bash
pip install -r requirements.txt
python scripts/screen.py
```

`docs/index.html`은 `fetch`로 데이터를 읽으므로 파일을 직접 열면 동작하지
않습니다. 로컬에서 볼 때는 서버로 띄우세요.

```bash
python -m http.server 8000 --directory docs
```

## 규칙 바꾸기

`config.yaml`만 수정하면 다음 실행부터 반영됩니다. 필터 임계값, 블록 가중치,
국면별 배분, 업종당 상한이 모두 거기 있습니다. 바꾼 뒤에는 Actions 탭에서
`Daily Screening`을 수동 실행(`workflow_dispatch`)해 결과를 바로 확인할 수
있습니다.

## 한계

- **낙폭에는 이유가 있을 수 있습니다.** 우량성 게이트는 재무·컨센서스 기준의
  방어선일 뿐, 소송·규제·수주 취소 같은 개별 악재는 걸러내지 못합니다.
  후보를 실제로 매매하기 전에 해당 종목의 최근 공시와 뉴스를 확인하세요.
- 스크리닝은 **전일 종가까지의 정보만** 사용합니다. 당일 갭, 장중 뉴스,
  실적 발표, 공시는 반영되지 않습니다.
- 실현 수익률은 시가 체결·종가 체결을 가정한 이론값입니다. 실제로는
  슬리피지와 호가 공백이 발생합니다.
- 팩터 가중치는 과거 데이터로 최적화한 값이 아니라 **사전에 정한 값**입니다.
  과최적화는 피했지만, 그만큼 이 가중치가 최선이라는 근거도 없습니다.
- 임시공휴일·특별 휴장은 `holidayskr` 갱신에 의존합니다.
